# Quest book workflow

The quest book is generated by Python. Never hand-edit `pack/config/ftbquests/quests/` (the build overwrites it).
Before writing anything, read `tools/quests/STYLE.md` (the house style, task types and pack gates) and the chapter
files you'll touch. On Windows, use `.venv\Scripts\python.exe` wherever the docs say `python3`.

## Hard rules
1. **Never rename or remove a quest key.** Quest ids are hashed from keys, so a rename wipes player progress on the
   live server. Titles, text, deps and tasks may change. To retire a quest, make it `optional=True` with a tick task.
2. **Only ask for things the player can really get.** Every id must be in `test/ids.tsv`. On top of that, check that
   our KubeJS didn't remove or gate its recipe: `grep -rn "<item id>" pack/kubejs/server_scripts`. Quest text must
   match the gated recipe (for example, the seed needs 4 H, 12 PE and 4 HF), not the mod's default recipe.
3. **Tier order:** a quest in chapter tN must not need an item first asked for in a later tier. Design tiers in
   docs/PROGRESSION.md are offset by one (design T3 = chapter t4).
4. **Required quests never depend on optional ones.** `secret=True` quests are optional automatically.
5. **Other packs' books (ATM10 and others) are All Rights Reserved.** Use them as an item checklist only
   (`tools/quest_compare.py`), and write all text ourselves. Never copy titles, descriptions or files.
6. **Real chemistry only.** Formulas and reactions must be correct. When unsure how something is made, read the recipe
   in the jar (`test/server/mods`) or write "check JEI". Never invent a recipe.
7. **Deps are the layout.** Don't spend time on x/y; `tools/layout.py` places quests from `deps`. Depend on the
   nearest quest that truly unlocks this one, not a far-off hub. Use `row=N` only to fix a bad result.
8. New chapter files must be added to `LAYOUT` in `tools/quest_data.py` (with their token rate in `TOKENS`).

## Steps
1. **Scope.** Name the chapter(s) and where the content enters the main path (the main-path quest the page's first
   quest depends on, plus a `links=[...]` entry back to it). For coverage ideas:
   `python tools/quest_compare.py "<ATM10 instance>\config\ftbquests\quests" --mod <modid>` (the path is in CLAUDE.md).
2. **Look up ids:** `grep -P '^modid:name\t' test/ids.tsv`. For entities, biomes and structures, grep the type column.
   Prefer `anyof([...])` and `anytag(tag)` over forcing one variant.
3. **Write the quests** in the chapter file. Use the key prefix of the chapter, the `subtitle`, and a 3 to 7 line
   `desc` (`&6` story, `&eWhat:`, `&eChemistry:`, `&eHow:`, `&eTip:`). Milestones are `size=2.0, shape="gear"`
   (capstone) or `size=1.5, shape="hexagon"` (section). Split big leaps into one quest per new machine or intermediate.
4. **Fast check** of just your chapters:
   `$env:QUEST_ONLY="a,b"; .venv\Scripts\python.exe tools\build_quests.py --check; Remove-Item Env:QUEST_ONLY`.
   The check also runs the cheap audit: cycles, unreachable quests, no tasks, wrong id kinds, required-behind-optional.
5. **Layout:** `.venv\Scripts\python.exe tools\build_quests.py --layout-report`. Look at your chapters' crossings and
   "lines through quests". Fix them with better deps first, then `row=`. Visual check:
   `.venv\Scripts\python.exe test\build_quest_preview.py`, then open test/preview (or the quest-editor launch config).
6. **Full build:** run `tools\build_quests.py` (no flags), then `packwiz refresh` in `pack\`. In PowerShell, refresh
   PATH first:
   `$env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [Environment]::GetEnvironmentVariable('Path','User')`.
7. **Obtainability (when items or recipes changed):** in the Terminal panel run `test\audit_dump.ps1`, then
   `tools\quest_audit.py --full`. Required-quest errors must be fixed. Explain warnings or put them in `ALLOW` with a
   reason. Java can't run in Claude's own shell on this PC, so smoke tests and dumps go through the Terminal panel.
8. **Wrap up:** add a `docs/CHANGELOG.md` entry with quest counts (`docs/QUESTS.md` is generated). Smoke test before
   pushing. Pushing and live restarts follow CLAUDE.md and the user's say-so.

## Special cases
- **Token shop** (market, shop_* chapters, `layout="manual"` grids): entries use
  `repeat=True, consume=True, locked_hidden=True, tokens=0`. Each one depends on a quest where the player makes or
  gets that item themselves ("buy more of what you've made"). Prices are in docs/research/shop_brief.md.
- **In-game edits** (FTB editor on a test client) are overwritten by the next build. Copy them into
  `tools/quests/<chapter>.py` first. Position tweaks from `tools/quest_editor.py` live in `tools/quest_overrides.json`
  and need no copying.
- **Big rounds:** give one chapter file to each parallel writer and have them run only the QUEST_ONLY check. One
  integrator then reconciles cross-chapter deps, rebuilds `test/ids.tsv` if needed (`test/build_id_index.py` after a
  smoke test), and runs the full build, smoke test and commit.

## Done means
- `--check` passes with no new warnings you can't explain.
- No new crossings or lines through quests in the chapters you touched.
- Every new item task is obtainable at its tier with the pack's real (KubeJS) recipes.
- Quest text matches the recipes, and no quest key was renamed.
